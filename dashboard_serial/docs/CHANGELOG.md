## V2.10 — 串口恢复策略：设备自动找回 + 确定性失败快速止损（2026-09-08）

- 背景：用户会拔插 USB。失败分两类，处理方式应当不同——FileNotFoundError（拔出/换口，COM 号会变）与 PermissionError（端口被串口监视器等外部程序占用，重试不会自愈），此前一律盲目重试 3 次且报错晦涩
- push.py 恢复策略：配置端口不存在时按 CP210x 的 VID:PID（10C4:EA60）自动扫回设备（换 USB 口零配置恢复）；彻底找不到或端口被占用抛 DeviceUnavailable——push_with_retry 遇之立即放弃不空转，错误信息人话化（"设备未连接…插回后下一轮轮播会自动恢复"/"串口被其他程序占用（串口监视器/烧录工具开着？）"）
- status 命令新增串口在线状态行（离线时列出系统现存串口，辅助发现换口后的新 COM 号）
- 附带发现：常驻服务被起了双份（启动项 VBS 的 pythonw 对 + 来源不明的 uv python 对，后者疑似僵尸；单飞锁与互斥体保护下暂无实害，待清理）
